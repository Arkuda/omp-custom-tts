# Kokoro-ru для Oh My Pi

Расширение для OMP 19.0.1: локальная русская озвучка через [zaakirio/kokoro-ru](https://huggingface.co/zaakirio/kokoro-ru), три голоса (`sveta`, `masha`, `dima`), экспорт WAV и автоозвучка финальных ответов. Синтез работает на CPU через ONNX Runtime, без Torch, GPU и системного eSpeak. Расширение не подменяет `omp say`, `/speech` и встроенный инструмент `tts`.

## Установка

Нужны OMP 19.0.1 и [`uv`](https://docs.astral.sh/uv/getting-started/installation/) в `PATH`. Установка создаёт окружение Python 3.12 и скачивает с Hugging Face словари, базовую модель и голос `sveta`. Понадобится около 1 ГБ свободного места плюс место под окружение Python.

**Windows x64**, из корня проекта в PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

**macOS 13+**, из корня проекта; OMP и `uv` должны работать нативно (`arm64` или `x86_64`), не под Rosetta:

```sh
sh ./setup.sh
```

Данные хранятся в `%LOCALAPPDATA%\omp-kokoro-ru` или `$HOME/Library/Application Support/omp-kokoro-ru`. Установщик создаёт `ready-v1` только после успешного офлайн-синтеза голосом `sveta`. Если скачивание прервалось, запусти тот же установщик: он переиспользует скачанные файлы.

При обновлении с версии, которая сначала писала временный WAV, запусти установщик ещё раз: он добавит `sounddevice` с PortAudio, не скачивая модели заново. Если старый демон ещё запущен, дай ему завершиться после пяти минут простоя: следующий запрос поднимет новую версию.

Затем свяжи пакет с OMP из корня проекта:

```sh
omp plugin link .
```

Пробный запуск без регистрации: `omp --no-extensions --extension .`

## Использование

| Команда | Действие |
| --- | --- |
| `/say-ru Привет, мир!` | Озвучить текст текущим голосом (изначально `sveta`). |
| `/say-ru --voice dima Привет, мир!` | Выбрать `dima` только для этой фразы. |
| `/speech-ru` | Открыть меню озвучки в TUI. |
| `/speech-ru voice` | Открыть выбор голоса. Можно и напрямую: `/speech-ru voice masha`. |
| `/speech-ru on` / `/speech-ru off` | Включить или выключить автоозвучку (только в интерактивном OMP); выбор сохраняется. |
| `/speech-ru status` | Показать состояние автоозвучки и текущий голос. |
| `/speech-ru stop` | Отменить проигрывание или его синтез, не прерывая экспорт. |
| `/speech-ru help` | Показать синтаксис и пример. |

После `/speech-ru ` и `/say-ru --voice ` OMP подсказывает доступные варианты. Выбранный голос используется для ручной и автоматической озвучки и экспорта без явного `voice_id`. Голос и автоозвучка — общие настройки OMP: они пишутся в `kokoro-ru.json` в каталоге агента (`~/.omp/agent`, на Windows `%USERPROFILE%\.omp\agent`) и восстанавливаются при смене сессии и перезапуске. Значения по умолчанию — `sveta` и выключенная автоозвучка; битый файл настроек не переписывается, а с предупреждением возвращает к ним.

Если файлов выбранного голоса нет, Kokoro-ru докачает их при первом синтезе и сохранит для работы без сети. `masha` использует ту же модель, что и `sveta`, и докачивает только файл голоса; `dima` также скачивает свою модель (около 138 МБ). Если сеть недоступна, уже скачанные голоса работают как обычно.

Автоозвучка по умолчанию выключена, а включённая остаётся включённой в новых сессиях и после перезапуска OMP. Она читает только финальный ответ: фрагменты в обратных кавычках внутри русского текста сохраняются, блоки кода, таблицы, изображения, URL и отдельные абзацы без русских букв пропускаются. Если включена штатная озвучка OMP, отключи её отдельно (`speech.enabled: false`), чтобы ответы не звучали дважды.

Ручная и автоматическая озвучка передают готовые фразы прямо на аудиовыход, без временного WAV: первая фраза начинает звучать, пока Kokoro синтезирует следующие. В автоозвучке это не меняет момент запуска: OMP сначала дописывает финальный ответ. На холодном старте всё ещё нужно загрузить модель и синтезировать первую фразу.

Все инстансы OMP с одним каталогом данных пользуются общим локальным демоном. Он запускается по первому запросу, держит одну копию модели, не накладывает озвучку из разных инстансов и завершается через пять минут простоя. `/speech-ru stop` и закрытие OMP отменяют запрос только своего инстанса; сам демон остаётся доступен остальным.

Инструмент `tts_ru` сохраняет mono PCM16 WAV (24 кГц) без проигрывания:

```json
{"text":"Привет, мир!","output_path":"speech.wav","voice_id":"masha"}
```

`voice_id` необязателен. Относительный путь считается от рабочего каталога сессии; родительский каталог должен существовать. Успешный экспорт заменяет существующий WAV; ошибка синтеза оставляет его нетронутым. Ручной ввод и экспорт ограничены 15 000 единиц UTF-16; автоозвучка берёт только начало ответа в пределах этого лимита. Одновременно работает один запрос: при занятости автоозвучка пропускается, ручной запрос или экспорт получают ошибку.

## Проверка платформ

На Windows 11 x64 (сборка 26300, OMP 19.0.1) проверены офлайн-синтез тремя голосами, WAV-экспорт, системный плеер, автоозвучка в TUI и совместная работа двух инстансов OMP через один демон, включая отмену запроса. Звук проверялся по WAV и состоянию плеера, не на слух. Для macOS 13 (`arm64` и `x86_64`) проверены метаданные Python 3.12 wheels и разрешение зависимостей; нативный запуск на macOS не проводился.

Потоковое воспроизведение отдельно проверено на Windows x64 с OMP 19.1.0: PCM поступает в плеер до окончания синтеза, `/speech-ru stop` останавливает активный поток, Markdown-фильтр и экспорт WAV работают. Потоковый плеер на macOS нативно не проверялся.

Сохранение настроек проверено на Windows x64 с OMP 19.1.1: два независимых процесса в `--mode rpc` восстанавливают включённую автоозвучку и выбранный голос из `kokoro-ru.json`, `/speech-ru voice` перезаписывает файл, не сбрасывая автоозвучку, а повреждённый файл возвращает значения по умолчанию с предупреждением.

При `WinError 126` проверь архитектуру Python и наличие [Visual C++ Redistributable x64](https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist). На macOS при ошибке `incompatible architecture` проверь `uname -m`, `file "$(command -v omp)"`, `file "$(command -v uv)"` и `platform.machine()` в Python из `.venv`. Для неподходящей `.venv` создай окружение заново: установщик не удаляет его автоматически.
